# OwnFee and related models

`OwnFee` represents a fee returned by an OWN commercial basket. Each fee combines a basket, a payment method, and, when applicable, a card network, channel, and installment range. The model is defined in `own.models` and uses the `own_fees` database table.

`OwnFee` records form a reference catalog. An `OwnPlan` does not modify this catalog: it links to a fee through `OwnPlanFee`, which stores the markup entered for that plan.

## OwnFee

| Field | Django type | Required | Description |
| --- | --- | --- | --- |
| `id` | `BigIntegerField(primary_key=True)` | Yes | The `cestaValorId` supplied by OWN. It is not generated by the database. |
| `basketId` | `ForeignKey(OwnBasket, PROTECT)` | Yes | The basket containing the fee. It uses the `basketId` column and exposes the reverse relation `fees`. |
| `value` | `DecimalField(20, 10)` | Yes | The current value returned by OWN in the `valor` field. |
| `baseMdr` | `DecimalField(20, 10)` | Yes | The minimum value/base MDR returned in `valorMinimo`. |
| `network` | `CharField(choices=OwnNetwork.choices)` | No | Card network. Null for products that are not network-specific. |
| `channel` | `CharField(choices=OwnChannel.choices)` | No | Physical or e-commerce channel. It may be null, as it is for anticipation fees. |
| `method` | `CharField(choices=OwnMethod.choices)` | Yes | Payment or charge method. |
| `installment` | `IntegerField` | No | An installment number or the lower bound of an installment range. |
| `upperInstallment` | `IntegerField` | No | The upper bound of the range; null for a single installment and non-installment methods. |

The names `basketId`, `baseMdr`, and `upperInstallment` preserve the terminology used by the integration. In Django code, `basketId` is the `OwnBasket` object, while `basketId_id` is its integer foreign key.

`basketId` uses `on_delete=PROTECT`. The remaining dimensions are text choices. Fees are ordered by `id`, and there is no additional uniqueness constraint across their dimensions: the external fee `id` is the identity of the record.

## Reference dimensions

### OwnBasket

`OwnBasket` identifies the commercial structure to which a fee belongs and uses the `own_baskets` table.

| Field | Django type | Description |
| --- | --- | --- |
| `id` | `IntegerField(primary_key=True)` | The basket ID in OWN. The loader supports IDs `117` and `333`. |
| `name` | `CharField(max_length=255, unique=True)` | Basket name returned by OWN. |

A basket exposes the reverse relations `fees` and `plans`.

### OwnNetwork

`OwnNetwork` is a text-choice enum with `Visa`, `Elo`, and `Mastercard` values. It does not have a database table. The plan form's "Padrão" tab is only a frontend shortcut.

### OwnChannel

`OwnChannel` is a text-choice enum with `Physical` and `Ecommerce` values. It does not have a database table.

### OwnMethod

`OwnMethod` is a text-choice enum for the payment or charge method.

The basket catalog recognizes `Pix`, `Debit`, `Credit`, `Installments`, `POS Rent`, `Top Bank`, and `Visa Voucher`.

## Relationship with plans

### OwnPlanFee

`OwnPlanFee` is the association model between `OwnPlan` and `OwnFee`. It uses the `own_plan_fees` table.

| Field | Django type | Description |
| --- | --- | --- |
| `id` | `BigAutoField` | Primary key generated by Django. |
| `plan` | `ForeignKey(OwnPlan, CASCADE)` | The plan. The reverse relation `plan.fees` returns `OwnPlanFee` rows, not `OwnFee` objects. |
| `fee` | `ForeignKey(OwnFee, PROTECT)` | A catalog fee. The reverse relation is `fee.plan_fees`. |
| `value` | `DecimalField(20, 10)` | The markup configured for this fee in the plan and sent unchanged during OWN signup. |

The `unique_own_plan_fee` constraint prevents the same fee from appearing more than once in a plan. Deleting a plan removes its `OwnPlanFee` rows, while deleting a fee referenced by a plan is blocked.

### OwnPlan

`OwnPlan` groups the fees used during OWN onboarding. In addition to its title, description, activity, basket, owning business, and audit fields, it exposes the reverse `fees` relation created by `OwnPlanFee`. The plan's basket also uses `ForeignKey(OwnBasket, PROTECT)`.

When a plan is created or updated through the API, its fees are submitted as a list of `{ "fee": <id>, "value": <value> }` objects. An update that includes `fees` replaces the previous list in full within a transaction. The serializer rejects duplicate fee IDs in a plan.

## Loading and synchronization

The `load_own_fees` command reads the `/consultarCesta` response, normalizes its products, and synchronizes fees by `cestaValorId`. Its default input file is `/app/load-consultar-cesta.json`; a different path can be supplied with `--file`.

Before writing any data, the command validates the expected set of 181 fees:

| Basket | ID | Count | Distribution |
| --- | ---: | ---: | --- |
| Bandeira | 117 | 41 | 12 per network and 5 without a network |
| Parcela | 333 | 140 | 46 per network and 2 without a network |

The synchronization creates or updates dimensions and fees in a single transaction. Fees missing from the new file are deleted only when no `OwnPlanFee` references them. Older fees already used by plans are retained to preserve historical data.

The loader also stores each basket's anticipation fee on `OwnBasket.anticipation_fee`. The plan form reads that value from `GET /own/baskets/{id}/anticipation-fee/`; it does not treat it as a plan fee row.

## API

`GET /own/fees/` requires authentication, is not paginated, and returns all fees ordered by `id`. `network`, `channel`, and `method` are text values, while `basketId` remains the basket ID.

```json
{
  "id": 14965,
  "basketId": 117,
  "value": "0.0000000000",
  "baseMdr": "1.7900000000",
  "network": "Visa",
  "channel": "Physical",
  "method": "Debit",
  "installment": null,
  "upperInstallment": null
}
```

Decimals are serialized as strings to avoid losing precision. The endpoint is read-only; the loading commands maintain the catalog.
