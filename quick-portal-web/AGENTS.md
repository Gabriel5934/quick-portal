# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this application. Run application commands from this
directory and Git commands from the parent monorepo root.

## Commands

```bash
# Development
npm run dev         # Start Vite dev server at localhost:5173
npm run build       # TypeScript check + Vite production build
npm run lint        # ESLint
npm run preview     # Preview production build locally

# Docker
docker compose up --build                        # Production build & run
docker compose -f docker-compose.dev.yml up      # Dev with hot reload
docker compose up --build --force-recreate       # Rebuild after dependency changes
```

These Docker commands target the standalone frontend project. To inspect the
running integrated `quick-portal` stack, run `docker compose ps` from the
parent monorepo root; its `app` service is this React frontend.

Tests use Vitest. Run `npm test` along with lint and build for relevant changes.

## Architecture

**Stack:** React 19 + TypeScript, Vite, MUI v9, TanStack Router v1, TanStack Query v5, React Hook Form + Zod.

**Routing** uses TanStack Router's file-based routing. `src/routeTree.gen.ts` is auto-generated by the `@tanstack/router-plugin` Vite plugin — never edit it manually. Route files live in `src/routes/`:

- `/` → `routes/index.tsx` — login page; redirects to `/home` if token exists
- `/signup` → `routes/signup.tsx`
- `/_authRoutes/` — layout route that guards all authenticated pages; its `beforeLoad` waits for the boot refresh (`requireSession` in `src/hooks/auth/session.ts`) and redirects to `/` when there is no session
- `/_authRoutes/home` → `routes/_authRoutes/home.tsx`

**Auth flow:** The access token is kept in memory only, in the TanStack Query cache under `["access_token"]` (`useToken` in `src/hooks/auth/useToken.ts`). The refresh token is an HttpOnly cookie set by the API; `POST /api/token/refresh/` rotates it and returns a new access token, serialized across tabs with the `quick-portal-refresh` Web Lock. Login takes the same lock, so its new cookie is set only after any logout or refresh in flight in any tab has finished, and bumps the `sessionGeneration` counter in `localStorage` before releasing it. Logout takes the same lock (so it waits for an in-flight refresh and blacklists the latest cookie), discards refresh results that complete after it started, notifies other tabs over the `quick-portal-session` BroadcastChannel (`src/hooks/auth/session.ts`), and skips each request attempt if `sessionGeneration` changed since it started (a login in any tab), so it never blacklists a newer session's cookie. Each logout attempt is aborted after `LOGOUT_TIMEOUT_MS` (10 s) and retried; login is aborted after `LOGIN_TIMEOUT_MS` (15 s, including the body read) and not retried, both through `fetchWithTimeout` (`src/hooks/auth/fetchWithTimeout.ts`). Refresh has no timeout: an aborted refresh may already have rotated the cookie on the server. The lock is not reentrant: never refresh while holding it. Login calls `POST /api/token/`, logout calls `POST /api/token/logout/`, and signup calls `POST /users/register/`. Token requests send `credentials: "include"` and `X-Requested-With: quick-portal`. The user email and the numeric `sessionGeneration` counter are the only `localStorage` keys; the generation holds no secret. API base is `VITE_API_BASE_URL` (`http://localhost:8080` in development).

**Feature modules** live in `src/features/<domain>/` with an `index.ts` barrel. Each feature owns its page components, form components, Zod schemas (`schemas.ts`), and TypeScript types (`types.ts`).

**Hooks** in `src/hooks/` contain API mutation hooks. `src/hooks/types.ts` defines shared types (e.g., `ValidationErrors`).

**Backend API error shape:** Errors are returned as `{ [field]: string[] }` (Django REST Framework validation errors) or `{ detail: string }` (DRF permission and auth errors). Hooks pass the parsed body to `firstError` from `#hooks/errors`, which returns the first string in the body, and throw it as an `Error` message, falling back to a generic message when it returns `null`. Do not index `errors[keys[0]][0]` directly: it misreads `detail` responses and throws on non-JSON bodies.

## UI

This project uses Material UI for components. Use the mui-mcp when working with this library

**Responsiviness**

Whe kept the default material ui breakpoints and they should be used for responsiviness. We are only concerned with 4 main breakpoints: phone, tablet and desktop. Heres how those devices fit whithin material ui breakpoints:

xs, extra-small: 0px -> Phone
sm, small: 600px -> Tablet
md, medium: 900px -> Tablet
lg, large: 1200px -> Desktop
xl, extra-large: 1536px -> Desktop
